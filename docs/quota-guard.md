# 额度守护 0.13.0：已有对话控制

账号额度由 account/read、account/rateLimits/read 每 30 秒刷新。Plus／Pro 的 primary、secondary 各自保存 1–95 的整数剩余阈值，旧标量复制到两项；参数校验失败不修改配置。任一触线保护全部选中目标；两窗口缺一不启用、不发新任务、不自动续聊。账号百分比可多人共同消耗，不换算个人 tokens。

## 接入与规则

quota.threads.browse 调用官方 thread/list，按更新时间读取未归档的交互历史，支持标题搜索与分页。quota.threads.attach 每批 1–20 个已列出的 ID，调用 thread/resume，只提交 threadId，保留原上下文与执行策略，不发生成请求。每个成功与失败单独返回。活动写入者冲突不伪装接管。累计最多 100 个目标。

quota.continuation 保存每条 {enabled,prompt}，内容最多 4000 字／16000 UTF-8 字节。守护开启或结果未知时不允许修改规则。总开关和逐条开关均开启才自动继续；留空用默认指令，先核对完成部分、继续剩余工作、不开展额外任务。completed 的最新回合跳过，包括有自定义内容的目标；未取得回合身份的空对话不自动发送。回合 completed 是协议状态，不等同于语义核验所有项目要求。

界面不再强制单一 resume_target；旧字段仅用于兼容旧配置。新规则互相独立，草稿不会被状态轮询覆盖，未保存规则阻止开启守护。可选的新任务仍采用 prepare → arm → chat；准备只创建空线程，发送前记录 start_pending，首次请求结果未知不自动再发。

## 两种控制范围

本地历史接入使用 AI Link 自己的 stdio Codex 进程。它可接入已释放的历史，不能抢占另一进程的活动写入者。当前本机原生桌面也是独立 stdio 服务，未开放可连接的共享入口，所以不能直接停止其中仍在运行的回合。JSONL、同一 CODEX_HOME 和历史列表都不是控制权限。

共享接入使用官方本机 WebSocket 服务。只接受 ws://127.0.0.1:端口 或 ws://[::1]:端口，不接受外部主机、重定向、路径、用户信息、查询和片段。使用原生选择器取得的本机凭据文件（最多 16 KiB、单行 ASCII token）；渲染器只获得文件名与不透明引用，主进程校验后映射路径。连接回环套接字绕过系统代理。断开只关闭客户端连接，不终止现有服务。

目标原客户端必须连接同一个共享服务。新建另一个服务无法迁移独立桌面的活动任务。传输在当前 Codex 文档中仍为实验性；默认共享入口不可用时，界面保留明确错误。应用不自动批准 agent 请求；已有对话保留其原执行权限，应用新任务使用只读沙箱。

## 状态与防重复

运行中：watching → interrupt_pending，先持久化再调用 turn/interrupt；相同 ID 的 interrupted 确认后转 paused。只有读取确认同一回合仍 inProgress 才以至少 5 秒间隔重试，最多三次。没有确认不宣称停止。单个中断或续聊结果未知，会保留该目标状态和错误，并继续处理其他选中目标。

interrupted／failed 的未完成目标可等待满额，completed 目标跳过。所有此前已知窗口仍存在、新鲜且都是 100%，个人上限有余量、事件完整、原回合身份一致且无较新活动时，paused／paused_idle → resume_pending，先保存意图再逐条发 turn/start。重置时间不代表真实满额。返回不明不重放；观察到新回合后解除未知状态，继续保护新回合。用户新回合取消旧计划，重启不自动开启守护。

多客户端读取与发起请求没有原子 compare-and-swap，不能完全消除竞争。某个目标读取失败时显示错误；控制调用超时后不将未确认状态显示为成功。

## 个人与团队统计

个人用量来自已归属线程的 tokenUsage 事件，以及每 120 秒扫描 CODEX_HOME/sessions（默认 ~/.codex/sessions）的 token_count。近 8 天、最多 50000 条，按分钟合并与累计区间去重。文件、事件和重启重叠不重复计入。采集损坏、队列溢出等已知不完整时，个人上限保守暂停。当前档案和套餐只是归类，多人共享目录无法自动识别人。团队账本独立，手动选择归属与导入。

token 上限是观察后暂停阈值；单次请求和最长约 2 分钟采集延迟可能超限，不是服务端硬预算。自动接入历史不会把此前共享消耗假装成该用户新增消耗。
